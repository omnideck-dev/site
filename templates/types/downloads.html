Before you start

  • A computer with macOS, Windows 11, or desktop Linux and at least 4 GB of memory.
  • Permission to install software. Setup installs the parts omnideck runs on, and your computer asks you to approve it.
  • An internet connection. The application image is about 680 MB on x86-64 or 850 MB on ARM64. A fresh setup also downloads operating-system components and Podman files, so the total can exceed 1 GB.
  • An AI model to connect. Use an API key from Anthropic, OpenAI, or OpenRouter, which bills API use to your account with them. Or use a model you already downloaded with Ollama on this computer.

omnideck is free and needs no omnideck account. More about connecting a model

Install and set up omnideck

  1. Install omnideck

    Open the DMG, drag omnideck onto the Applications shortcut, then eject the disk image.

  2. Open omnideck

    Open omnideck from Applications. The first time, macOS checks the app and may ask whether you want to open an app downloaded from the internet. Select Open.

    If macOS instead says it can’t verify omnideck or that it may harm your Mac, don’t open it. Move it to the Trash, download the DMG again from this page, and check its fingerprint.

  3. Set up omnideck

    Select Set up omnideck. Setup gets your Mac ready and downloads omnideck’s files. It takes several minutes, and you can play Agent Dash while you wait.

  4. Finish setup

    When setup reports that omnideck is ready, select Open omnideck.

Troubleshooting

If setup stops

omnideck explains what stopped setup and shows a next step, such as approving a permission prompt or restarting Windows. Follow that step, then select Try again when it is offered. If it stops again, open Technical details and share them in the community Slack or a GitHub issue.

Windows: WSL initialization times out

If Technical details contains Wsl/Service/CreateInstance/ERROR_TIMEOUT while preparing WSL, save your work, restart Windows, and reopen omnideck to resume setup. Use the separate memory.max workaround below only if that error appears.

Windows: setup stops with a memory.max error

On Windows 11 25H2 with WSL 3.0.1 and Podman 6.0.2, desktop 0.1.0-beta.13 can show Setup didn’t finish with crun: open memory.max for writing: No such file or directory in Technical details. The issue is not fixed in desktop 0.1.0-beta.14. The same runtime issue affects CLI v0.11.0-beta.6 through v0.11.0-beta.8. CLI beta.7 adds a direct link to these recovery steps; it does not change WSL settings.

The following workaround was checked through desktop setup and opening the workspace, and through CLI startup and restart with its memory limit intact.

It changes WSL’s resource-control isolation for all WSL 2 distributions in your Windows account.

  1. Close omnideck and save any work in your WSL distributions.
  2. Open %UserProfile%\.wslconfig in a text editor, or create it if it does not exist. Keep all existing settings. In its [wsl2] section, add or update isolateDistroCgroup=false. Add the section only if it is missing: 
    [wsl2]
isolateDistroCgroup=false
    Save the file as .wslconfig, without a .txt extension.
  3. In PowerShell, run wsl --shutdown. This stops every running WSL distribution in your account.
  4. Reopen omnideck, or run omnideck for the CLI. Desktop setup resumes; select Open omnideck when it reports that it is ready.

See Microsoft’s WSL configuration reference for the setting’s scope, and the tracked Windows runtime issue for updates.
